# 让 Codex 少猜、少越界的指令规律

这些规律来自对既有任务 brief 的阅读与抽象。这里只记录通用方法，不收录私人原文、来源文件名、个人信息或实际业务数据。

| 规律 | 要解决的问题 | 工具中的体现 |
| --- | --- | --- |
| 写出结果，再写验收条件 | “做一下”无法判断完成 | 目标、成功标准字段及相应 lint 规则 |
| 可读、可写范围分开说明 | 搜索范围不应自动变成修改权限 | 范围白名单字段与护栏 |
| 列出明确禁区 | 顺手重构、改依赖、操作外部系统 | 禁区字段与危险动作检查 |
| 错误时停下，保留证据 | 失败后盲目重试、删记录或换服务 | 停止条件及保留产物护栏 |
| 只引用真实材料 | 为了补全报告而编数字、链接或结论 | 数据真实性规则与护栏 |
| 缺失标未知，推断标推断 | 把未知当事实、把建议当证据 | 不确定事项规则 |
| 分清事实、示例和模拟 | 示意结果被误认为实测 | 明确标注示例，不虚构验证记录 |
| 先做一个样例再批量 | 批量放大格式或理解错误 | 条件触发的批量检查点 |
| 分步骤并写清依赖 | 多任务混在一句话里导致遗漏 | 多任务提示与编号步骤建议 |
| 写清交付位置、格式、语言 | 产物散落或只剩口头答复 | 输出字段及 Markdown 结构 |
| 用实际检查支持完成声明 | 未验证就宣称达标 | 验证规则、完成标记及未完成说明 |
| 从断点继续并保留已有成果 | 重复劳动或覆盖有效产物 | 续做护栏与默认不覆盖输出文件 |

可复用的最小结构：目标、白名单、禁区、验收条件、交付位置。将停止条件、真实性、验证和确认点作为通用护栏附在后面。具体数值、文件和对象应由任务本身提供；工具只负责提醒和组织。

“完成”是验收后的结果标记。生成 brief 或填写字段不代表任务已经完成。
